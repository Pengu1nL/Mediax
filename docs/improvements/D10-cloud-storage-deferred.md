# D10：云端存储集成方案 —— 暂缓

> 状态：暂缓  
> 决策日期：2026-04-28

---

## 一、原问题

Mediax 的前身架构（FSA 本地文件夹绑定）仅支持本地素材库，不支持 Google Drive、OSS、S3 等云端存储。D10 原计划在 Library 中增加云端存储集成选项。

## 二、架构变化

D9（素材批量知识化）对整个存储架构进行了根本性重构：

- 移除了 File System Access API 和本地文件夹绑定
- 素材上传改为 HTTP multipart upload，由服务端接管存储
- 知识产物（`.md` 文档 + 原始文件）统一存入 `knowledge/` 目录
- 设计了可插拔的 `KnowledgeStorage` 接口（本地 / S3）

D10 的存储抽象方案已在 D9 方案文档中预先设计，**接口和扩展点已就位，但云端存储实现暂不启动**。

## 三、暂缓原因

1. **当前阶段无多机部署需求**：Mediax 目前是单机原型阶段，本地文件系统满足需求
2. **知识库体量可控**：`.md` 文档和图片在单机磁盘足以承载，无扩容紧迫性
3. **用户群体尚未扩展到团队协作**：D33（多用户与权限体系）是云存储的前置依赖
4. **降低早期复杂度**：引入 S3 SDK 和云服务配置会增加部署门槛，不利于当前阶段的快速迭代

## 四、未来重启条件

满足以下任一条件时重启 D10：

- 需要多实例部署（水平扩展）
- 知识库文件总量超过单机磁盘容量
- 引入团队协作（D33），需要共享存储
- 用户明确要求对接特定云存储服务

## 五、重启时的技术基础

D9 已预留的扩展点：

- `KnowledgeStorage` 接口（`save` / `read` / `delete` / `exists` / `list` / `test`）
- `StorageConfig.backend` 字段（当前固定为 `"local"`）
- Settings 页面中预留的存储设置区块位置
- 迁移脚本框架

重启时只需：
1. 实现 `S3KnowledgeStorage`
2. 在 Settings 中添加 S3 配置 UI
3. 编写本地 ↔ S3 迁移脚本
