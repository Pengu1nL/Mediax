# D1：Onboarding 表单分步体验重构

> 状态：方案已产出  
> 涉及范围：前端  
> 依赖：无（为 D2、D3、D4 预留接口）

---

## 一、问题回顾

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | 页面顶部写死 `Step 1 OF 3`，但实际只有一个长表单，没有第 2、3 步 | 高 |
| 2 | 9 个字段在同一屏铺开，视觉压力大，认知负荷高 | 高 |
| 3 | 必填字段（3 个）和可选字段（6 个）在视觉上几乎无区分 | 中 |
| 4 | "禁用表达"、"审核策略"等字段对首次用户难以决策，却与其他字段并列展示 | 中 |
| 5 | 审核策略三个选项没有任何解释文字，用户不理解行为影响 | 低 |

---

## 二、方案设计

### 2.1 整体思路

将虚假的 "Step 1 of 3" 变成 **真正的 3 步向导**，每一步聚焦一个语义主题，降低单屏认知负荷。

```
 Step 1          Step 2          Step 3
 品牌身份  ──→  品牌声音  ──→  审核设置 + 总览
 (2-3 字段)     (5 字段)        (1 设置 + 汇总卡片)
```

### 2.2 步骤划分

#### Step 1：品牌身份（必填核心信息）

| 字段 | 必填 | 说明 |
|------|------|------|
| 品牌名称 | 是 | 品牌名称，文本输入 |
| 所属行业 | 是 | 下拉选择（选项扩充属于 D3，本次仅保留现有 4 选项 + 为 D3 预留"其他"入口） |
| 核心关键词 | 否 | 逗号分隔，文本输入 |

**设计要点：**
- 2-3 个字段，用户 30 秒内可完成
- 完成 Step 1 后用户已有"进展感"，降低流失
- Step 1 暂不做验证拦截（可以点"下一步"），到 Step 3 提交时统一校验

#### Step 2：品牌声音（AI 生成质量的直接影响因素）

| 字段 | 必填 | 说明 |
|------|------|------|
| 品牌简介 | 是 | 多行文本，textarea 4 行 |
| 品牌语气 | 否 | 文本输入 |
| 目标受众 | 否 | 文本输入 |
| 品牌定位 | 否 | 文本输入 |
| 禁用表达 | 否 | 逗号分隔，文本输入 |

**设计要点：**
- 顶部加**内联提示**："以下信息将直接影响 AI 生成内容的风格和质量，填写越详细效果越好"
- 品牌简介放在最前，其余字段按重要性排列
- 每个字段组右侧预留 **"AI 建议"按钮**（icon-only，当前 `disabled` + `opacity-30`，title 提示"AI 辅助填写即将上线"），为 D2 预留 UI 位置
- "AI 建议"按钮样式：小型圆角按钮，带 Sparkles/Magic 图标，disabled 态半透明

#### Step 3：审核设置 + 总览确认

**审核策略选择器：**

| 选项 | 标签 | 说明 |
|------|------|------|
| `manual_required` | 必须人工审核 | 每次 AI 生成内容后，需要你手动审核通过才会进入发布队列 |
| `auto_if_low_risk` | 低风险自动通过 | 常规内容自动发布，仅敏感内容需要审核 |
| `auto_publish` | 自动发布 | AI 生成后直接标记为已发布（适合熟悉平台后使用） |

**设计要点：**
- 审核策略改为卡片式选择（radio card），每张卡片包含标题+描述文字，替换当前的裸 `<select>`
- 下方展示**品牌档案总览卡片**：以只读卡片形式展示 Step 1 + Step 2 填写的所有信息
- 每项右侧放一个小型编辑图标（`Edit3` / `Pencil`），点击跳回对应步骤
- 总览卡片使用现有 `bento-card` 风格，浅灰背景圆角卡片

### 2.3 步骤指示器

位于表单卡片内部顶部，标题上方：

```
  ●━━━━━━●━━━━━━○
  品牌身份  品牌声音  审核确认
```

- 3 个圆形步骤节点，用横线连接
- 已完成步骤：实心圆（signal-orange）+ 实线连接
- 当前步骤：实心圆（signal-orange）+ 虚线连接到下一步
- 未完成步骤：空心圆（zinc-300）+ 虚线连接
- 已完成步骤可点击跳回（cursor-pointer）
- 步骤文字标签在当前步骤时加粗，已完成步骤正常字重

### 2.4 底部导航

```
Step 1:            [稍后完善]     [下一步 →]
Step 2:   [← 上一步]              [下一步 →]
Step 3:   [← 上一步]              [保存并进入品牌页 →]
```

- "稍后完善"按钮在 Step 1 显示，Step 2/3 替换为"上一步"
- 主操作按钮在右侧，保持现有样式（ink-black 背景，白色文字）
- Step 1→2 无校验，Step 2→3 无校验，Step 3 提交时校验必填字段
- 如果 Step 3 提交时校验失败，自动跳转到对应步骤并高亮缺失字段

### 2.5 步骤切换动画

使用 `motion/react` 的 `AnimatePresence` + `motion.div` 实现步骤间切换动画：

- 进入：从右侧滑入 + 淡入（`x: 20 → 0, opacity: 0 → 1`）
- 退出：向左滑出 + 淡出（`x: 0 → -20, opacity: 1 → 0`）
- 前进/后退方向一致（不做方向区分，保持简洁）

### 2.6 数据持久化

- 所有表单状态保持在 `Onboarding` 组件顶层（与现行方式一致）
- 切换步骤不丢失已填数据（state 都在父组件）
- `useEffect` 初始化从 `brand` 状态同步（保留现有逻辑）
- 点击"稍后完善"时已填数据通过 `saveBrandProfile` 保存（保留现有行为）

## 三、组件结构

```
Onboarding (page component)
├── StepIndicator        (内联组件，3 个步骤节点 + 标签)
├── AnimatePresence
│   ├── Step1Content     (内联，品牌名称 + 行业 + 关键词)
│   ├── Step2Content     (内联，品牌简介 + 语气 + 受众 + 定位 + 禁用表达)
│   └── Step3Content     (内联，审核策略卡片 + 品牌档案总览)
└── BottomNavigation     (内联，上一步/下一步/提交按钮)
```

所有子组件内联在 `Onboarding.tsx` 中，不拆分独立文件（除非后续有其他页面复用）。
